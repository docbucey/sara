2. Core Functional Blocks (The "Grammar")
Regardless of the language used, the Protolingua script should follow this sequence:

@init: Auto-detects the host environment (Standard Python, Protolingua SDK, or External API).

@bridge: Maps native language types (like Python lists or C# arrays) into Protolingua Universal Objects.

@execute: The logic layer where only Protolingua-specific verbs are used.

🛠️ The "No-Import" Polyfill (Python Example)
To allow a user to use "traditional Python" without writing import, you can provide a Bootstrap Wrapper. This is the "glue" that makes the universal template work.

Python
# --- THE BOOTSTRAP (Hidden from the user) ---
import protolingua_sdk as proto

# Pre-injecting the SDK into the global namespace
globals().update({
    'absorb': proto.absorb,
    'echo': proto.echo,
    'sift': proto.sift,
    'Universe': proto.CoreContext()
})

# --- THE USER'S UNIVERSAL SCRIPT STARTS HERE ---
# Notice: No imports, no boilerplate. 

data = absorb() 
if sift(data):
    echo("Protolingua Protocol Active")

Protolingua Scripting Requirements
Environment Agnosticism: Logic must not rely on language-specific standard libraries (e.g., no math.sqrt, use proto.sqrt).

Implicit Context: Every script is executed within a Universe scope where all Protolingua verbs are top-level globals.

Strict Typing: Data passed between functions must be wrapped in the ProtolinguaObject wrapper to ensure cross-language compatibility.

Signal over Syntax: Use functional chains (e.g., absorb().sift().echo()) to minimize the need for variable declarations that differ between languages.
